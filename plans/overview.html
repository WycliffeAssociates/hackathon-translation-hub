WACS Dashboard Rebuild

A small service that sits next to Forgejo's files and answers high-level questions about the whole Bible translation catalog, through an HTTP API and a dashboard on top of it.

The idea

Forgejo stores the code shape. We store the Bible shape.

WACS hosts thousands of translation repos on Forgejo. Forgejo sees them as git repos: files, commits, branches. The questions people ask are about Bibles: which languages have a New Testament, which books exist, which projects are healthy, who is actively working.

The best way to get that high-level view is to sit right next to the files and read them for a different purpose. We are not recreating git or Forgejo. We read the same repos, read-only, and index what they mean as scripture: languages, books, manifests, lint health.

How it works

In a few lines

  • Public repos only, to be safe.
  • A soft poll, not events. It checks Forgejo's database every few minutes for changed repos, so a missed event or a restart never leaves it out of date. It's fast because the files are right there.
  • Bible-shaped queries. By language, by book, by resource type, by activity. Maybe a heat map later.
  • Keyed by git SHA. Results like lint counts are stored against the exact content they came from, so nothing is recomputed until the text changes.
  • One Bible per language. A consolidated view of the many BTT Writer projects for a language, built from the primary ones.
  • Rendered on demand. Opening a repo shows its current text, never a stale pre-render.
  • Rust, because the USFM parsing and linting it builds on (scripture-kitchen) is Rust. It's pinned by git tag.

Indexing the entire catalog from scratch takes well under a minute in early tests.

Order of work

Increments

1 · first

Catalog API

Index every public repo's manifest and books. Filter by language, subject, book and owner. No UI yet.

2

Health

Lint counts and manifest problems, so you can ask "which projects need attention?"

3

One Bible per language

Stitch the primary BTT Writer projects into one view per language.

4

Dashboard

A repo page with rendered text, lint findings in place, and releases.

Out of scope

What this is not

  • Not a replacement for Forgejo, and it never writes to it.
  • Not a reader, an editor or a new linter.
  • Not full-text search across Bibles.
Getting started

Dev environment

The repo ships a MariaDB with 32,575 public repo rows and 1,441 real bare repos copied from the dev server, including the full wa-catalog and complete NT _text_reg sets.

docker compose up -d db
export DATABASE_URL=mysql://dashboard_ro:dev@127.0.0.1:3306/gitea
export REPO_ROOT=./dev-data/repositories
scripts/pull-more.sh 50 'regex'   # more repos from wacsdev
A detailed plan, with schemas and code sketches, is in plans/architecture.html in the repo.
